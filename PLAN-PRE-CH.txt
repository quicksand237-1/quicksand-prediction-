POLYMARKET 计数市场预测器：实现计划

0. 目标

构建一个可靠的研究和模拟交易系统，用于七天社交帖子计数市场。系统必须估计最终计数分布，将其转换为每个 Polymarket 结果区间的概率，将这些概率与可成交价格比较，并拒绝不安全的数据或执行条件。

1. 数据可靠性优先

1.1 在每个活跃市场期间持续运行 XTracker 采集器。
- 每 30 到 60 秒轮询一次。
- 保存每次响应、计数样本、请求时间戳和来源新鲜度。
- 保留帖子 ID、时间戳、帖子类型、文本和原始来源 JSON。
- 不要把市场结束后的导出作为主要历史来源。

1.2 添加明确的数据来源质量字段。
- 为每个窗口添加覆盖状态：已验证、部分、过期、未知。
- 在结算后将本地最终计数与 Polymarket 已结算区间比较。
- 当本地计数落在区间外时，记录缺失计数的下限和上限。
- 默认训练和评估中排除部分或过期窗口。

1.3 添加独立核对。
- 使用 XTracker 作为与结算规则对齐的来源。
- 在可用时捕获 X 公开页面或 API 观察结果作为次级审计来源。
- 在来源之间比较帖子 ID 和时间戳。
- 保存分歧，但不覆盖与结算规则对齐的来源。

2. 市场数据和微观结构

2.1 收集更丰富的价格数据。
- 在可用时保存 Yes 和 No token 数据。
- 收集最优买价、最优卖价、价差、中间价、最后成交价、深度和成交量。
- 保存每个订单簿快照及其采集时间戳。
- 将 Gamma 元数据、CLOB 历史和实时快照保存到不同表中。

2.2 验证互斥结果分布。
- 在每个区间选择一个 Yes 价格后，要求概率质量接近一。
- 将超出可配置上下概率质量限制的分布标记为无效。
- 检测缺失区间、重复区间、过期区间和不一致时间戳。
- 仅使用同步或近似同步的区间作为市场隐含特征。

2.3 建模交易可行性。
- 估计吃单费、挂单返佣、滑点、穿越价差成本和最小下单量。
- 拒绝小于总执行成本加不确定性准备金的理论优势。
- 为每个结果添加流动性和最大持仓限制。

3. 特征工程

3.1 发帖过程特征。
- 当前计数、已过小时、剩余小时和累计节奏。
- 1、3、6、12、24 和 48 小时滚动速度。
- 到达间隔特征：均值、方差、突发分数和零发帖连续长度。
- 一天中的时间、一周中的日期、市场启动星期和夏令时指标。

3.2 内容和事件特征。
- 将观察到的帖子分类为转帖、引用帖、主贴、类似回复和不确定。
- 使用本地或 API 分类器从帖子文本中提取主题聚类。
- 导入结构化外部事件：发布、财报、政策、诉讼、冲突、产品公告、选举、旅行和重大新闻。
- 使用时间衰减事件影响，而不是只使用累计事件数量。

3.3 市场特征。
- 市场隐含期望计数、熵、集中度和区间层面的偏斜。
- 价格变化、订单流不平衡、价差、深度和成交量加速度。
- 过程模型预测与市场隐含预测之间的差异。
- 按已过小时桶统计的历史校准误差。

4. 统计模型

4.1 保留现有 Ridge 模型作为基线。
- 仅用已验证数据重新训练。
- 使用净化后的时间切分，因为相邻七天窗口会重叠。
- 按已过小时桶报告 MAE、RMSE、区间准确率、校准和误差。

4.2 添加计数分布模型。
- 对过度离散计数使用负二项回归。
- 对剩余帖子使用分段泊松或负二项模型。
- 为不活跃时段添加零膨胀部分。
- 添加分层的星期和小时效应。

4.3 添加自激突发模型。
- 拟合 Hawkes 风格强度模型或更简单的突发状态模型。
- 在帖子聚集出现后提高短期强度。
- 随时间衰减突发强度，并设置上限以防止预测不稳定。

4.4 添加贝叶斯不确定性。
- 当来源覆盖不完整时，将真实计数视为潜变量。
- 将结算区间作为历史市场的区间删失观察。
- 生成最终计数的后验样本，而不是只生成一个点预测。
- 直接将样本转换为结果区间概率。

4.5 组合模型。
- 混合 Ridge、计数过程、突发和市场隐含预测。
- 在滚动验证集上学习混合权重。
- 即使点预测 MAE 较低，也要惩罚校准较差的模型。

5. 评估设计

5.1 Walk-forward 评估。
- 对每个目标市场，只在其开始前结束的更早窗口上训练。
- 清除与目标区间重叠的任何训练市场。
- 在每个 walk-forward 折内重新拟合特征标准化和模型参数。

5.2 小时回放。
- 从第一小时到市场结束，每小时生成预测。
- 保存预测最终分布、区间概率、本地观察计数、结算区间、来源质量和市场数据质量。
- 报告随已过时间变化的误差曲线，而不只报告最终汇总指标。

5.3 校准评估。
- 对每个预测区间概率，按概率桶对预测分组。
- 比较预测概率与已实现区间频率。
- 报告 Brier 分数、对数损失、期望校准误差和可靠性图。

6. 交易决策层

6.1 将最终计数分布转换为可交易概率。
- 在每个市场结果范围内求概率质量之和。
- 对开放尾部区间，积分分布尾部，而不是使用中点。
- 对 Yes 买入决策使用卖价，对 Yes 卖出决策使用买价。

6.2 定义优势和不交易规则。
- 对 Yes 买入，edge = 模型概率 - 可执行买入价格。
- 要求优势超过费用、价差、滑点、模型不确定性和安全边际。
- 当来源新鲜度、价格同步性或流动性失败时拒绝交易。
- 在接近结算时，如果来源可能仍漏掉最近删除的帖子，则拒绝交易。

6.3 风险限制。
- 每个市场、每个区间和相关重叠窗口组的最大持仓。
- 每日损失上限、回撤上限和下单速率上限。
- API 错误、来源过期、异常概率质量或模型漂移时的熔断开关。
- 在达到 walk-forward 和校准目标前，默认使用模拟交易。

7. 存储和运行

7.1 模式扩展。
- 添加 order_book_snapshots、source_audits、model_runs、hourly_forecasts、paper_orders、paper_fills 和 risk_events 表。
- 为所有模型、特征定义、代码版本和训练数据集添加版本。

7.2 定时任务。
- 活跃市场采集器：30 到 60 秒。
- 价格和订单簿采集器：流动性存在时每 10 到 30 秒。
- 特征和预测任务：每小时一次，外加事件触发刷新。
- 结算核对任务：市场结算后执行一次，并在 24 小时后再次执行。

7.3 可观测性。
- 为每个请求、预测、拒绝和订单写入结构化 JSON 日志。
- 导出每日数据质量和模型质量汇总。
- 对来源过期、概率质量异常、重复 API 失败或大幅预测漂移发出告警。

8. 实现顺序

步骤 A：添加来源覆盖和结算核对表及报告。
步骤 B：在修改模型前，持续采集多个活跃市场。
步骤 C：添加同步 CLOB 订单簿快照和价格质量验证。
步骤 D：扩展小时回放，保存完整区间概率和校准指标。
步骤 E：实现负二项剩余计数模型，并与 Ridge 比较。
步骤 F：为已结算区间历史标签实现区间删失贝叶斯模型。
步骤 G：添加具有费用、价差、流动性和风险限制的模拟交易器。
步骤 H：运行多市场 walk-forward 模拟交易周期并审查校准。
步骤 I：仅在有文档化的安全和性能门槛通过后，考虑有限的实盘执行。

9. 验收门槛

- 不允许在过期、部分、未验证或不同步的数据上自动交易。
- 每次模型运行都可以从保存的数据库行和模型元数据复现。
- Walk-forward 评估不使用重叠标签或未来标签。
- 区间概率必须经过校准，而不只是点预测准确。
- 真实费用和滑点后，模拟预期优势仍为正。
- 在来源和 API 失败期间，模拟交易风险控制能够正确运行。
